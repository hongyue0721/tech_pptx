# 渲染、版式与真实PPTX验收

## 导出器准入

M0用固定最小DeckSpec跑四种布局、中文、长标题和多行正文；生成PPTX并在目标Office打开且编辑文本。记录依赖来源、许可、版本、命令和文件hash。准入结果（2026-09-21，ADR-11）：ppt-edit 因 R05 来源/授权核验未闭合未通过准入，按"不通过则切清晰依赖"选定 python-pptx==1.0.2（MIT）为唯一激活导出实现；字面备用 PptxGenJS 不激活（避免 Node 侧导出链与跨语言部署负担）。不得把来源不明patched WASM作为必须保住的创新。

备用实现不改变课件语义模型，只实现固定布局。PPTD是选定出口的中间文件，不是必须为了技术叙事保留的第二业务真源。任何替换必须更新ADR及实际宣传。

## 四类布局

固定16:9。title：封面/章节，1个标题+1段教学说明。concept：标题+2—4个关键事实。two_column：左右两组同层内容。process_example：最多4步或一组明确假设与课堂问题。

默认正文24pt、标题32pt、页脚12pt；正文22pt为硬下限。推荐侧边距0.45英寸。数值是本Demo设计约束，并非无条件投影可读保证。最多6个事实块、视觉密度超过限额先拆页。不要用所有框无限缩小字号来“通过QA”。

统一主题 `classroom_v1`：白底、深色正文、蓝色点缀。AnyUI用于网站按钮/表单，不参与幻灯片主题渲染；网页玻璃效果不应污染导出PPT。

P0只原生文本、简单形状、直线/箭头；不生成复杂数学公式/SmartArt/动态图，不自动找图片。引用页脚简短显示资料代号+物理页；完整quote与核验在Web侧和伴随evidence-report.json。

## 必须确定性处理

坐标/字号/颜色来自固定布局函数；输入文本统一转义。禁止模型注入任意SVG、脚本或远端URL。长词、英文API名、中文换行和缺字是专门测试项。

文本溢出不可只靠字符数保证。第一层字符和块数预算；第二层渲染图像人工检查；若启用自动视觉检查，它也是辅助，不给“绝无溢出”保证。

## 预览分级

PPTD_RENDER：同版PPTD经编辑器生成图，仅代表中间稿。

PPTX_RENDER：导出文件在明确版本渲染引擎打开后生成图，更接近交付文件；仍需目标Office抽验。

OUTLINE：Vue按DeckSpec显示结构化内容，显著标“结构预览，最终版式以导出文件为准”。预览失败不影响已提交语义版本；不能偷偷用旧截图显示。

每页图有project/version/renderer/theme/font键。P0先保证结构预览和真实PPTX；高保真图在M0确认环境后提升为P0或列P1，最终材料按实际能力填写。

## 运行隔离

渲染子进程单任务唯一目录，固定依赖已安装；不在用户请求中运行npx/pip补依赖。受限用户、无额外Key环境、禁止外网资源、时限120秒（M0校准）、stderr限额、失败清理。

若启用Chromium，最多一个受管理实例/任务，退出后检查孤儿进程。不得为赶进度将未知代码以root和无限制网络运行。

## PPTX验收层次

L1：文件存在、ZIP/OOXML结构与幻灯片数量、引用关系完整。

L2：检查每页文本对象可编辑；不能把整页截图塞进PPTX后宣称可编辑文本。

L3：在目标WPS或PowerPoint打开，逐页检查中文字体、遮挡、溢出、段落与页脚；修改一个标题并保存再打开。

L4：同输入三次导出可接受；允许ZIP时间戳差异，比较语义/结构而不是要求二进制字节完全相等。报告tested_on具体软件和版本，不概括支持所有Office。
