# 给鸿岳｜准备、节奏与验收

## 你负责什么

你的核心工作是确定范围、批准费用/公开操作、判断验收结果，不是和Agent竞赛写CRUD。核心代码由你统一集成；朋友负责按测试步骤复现、检查视频和整理真实反馈，不为凑人数虚构开发分工。实际核心成员要求见[S02]。

## 开工前需要的资源

| 事项 | 最低准备 | 谁处理 |
|---|---|---|
| 报名窗口 | 校内截止、推荐/补报名权限、材料上传栏目 | 你或朋友联系学校 |
| 团队 | 满足人数与资格、实际贡献分工、导师信息口径 | 你 |
| 码道 | 可登录账号、有效席位、CLI、Skill功能；自定义模型权限 | 你核实控制台 |
| 开发模型 | 协议、模型ID、Key、可用额度、允许工具调用与流式 | 你本地配置，不粘入仓库 |
| 运行时模型 | 单独Key与预算、固定端点、JSON输出能力 | 你授权后测试 |
| 环境 | Ubuntu 24.04优先，Python3.12、Node22.12+；版本由M0精确锁定 | Agent执行 |
| 云演示 | 一台可负担实例、磁盘、访问方式；公网开放需确认 | 你批准 |
| 导出依赖 | ppt-edit来源/内嵌资产授权；不清楚就切受控备用出口 | 你确认、Agent记录 |
| 素材 | 本包PDF足够启动，不需要买数据库/找整本教材 | 已随包提供 |

4核8GB是含浏览器渲染的预算规划参考，不是已测最低配置。无浏览器时可从较小实例实测；不建议为Demo买GPU。记下CPU/RAM、模型时延后再决定配置。不要因本包写了某个版本就自动购买产品。

## 第一天只看三个结果

码道能用选定模型完成一次“读文件→改文件→跑测试→导出会话”；固定输入能导出一份可打开并修改文字的PPTX；AnyUI最小页面能编译并完成上传、弹层和按钮交互。

任一项失败都先定位。不要一边渲染器未通，一边让Agent铺满前后端。账号权限可由你/朋友与技术工作并行确认，但在权限问题解除前不承诺参赛资格或全流程可用。

## 你怎样验收，而不必读完代码

要求现场完成：上传讲义→确认大纲→出8页课件→点开一条引用→拆页→拒绝不受支持的补充→撤销→下载并改一个文本框。

再换文件名、调整课题顺序、换一份变体材料。检索器不能靠文件名触发预置答案。问Agent“哪些是live，哪些是fixture，哪些测试没跑”，比问“写了多少行”更有用。

## 工时与止损

本包以9月18日启动、9月23日完成主要演示、9月24日交付材料为目标。全国窗口见[S02]，更早校内截止优先。规划估计需要约35—50小时有效主开发/验收工作，另留6—10小时不确定性；并非保证。

每天限制同时在制任务为1个，不靠通宵补无边界需求。第1天导出链不通且来源不明，切备用导出器；第3天仍不能完成PDF→DeckSpec→PPTX，砍自动视觉复检和高级编辑，但不能砍真实导出、来源校验或码道实际开发记录。

## 朋友可以帮忙却不打扰你

朋友A按 `demo-data/evaluation/cases.json` 复现测试并登记结果；朋友B核对报名、整理录屏和材料错别字。问题统一写在一张验收表，约定每天一次集中交接，非阻塞问题不随时插入开发。能不能这样分工由实际成员情况决定，不虚填。

## 必须由你最终决定的未决事项

学校窗口和参赛资格；码道账号权限；外部API的具体提供商/模型/费用上限；是否允许云端处理资料；是否公开部署；ppt-edit资产来源。其余技术实现按冻结规格推进，不再开新一轮开放式选型。
