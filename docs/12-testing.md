# 测试策略与验收标准

## 1. 不混淆四类证据

PACK_STATIC：本文档包的Schema、引用、数据PDF和清单检查。APP_OFFLINE：未来业务代码使用可控fixture的测试。APP_LIVE：真实指定模型与真实导出器测试。HUMAN_REVIEW：目标浏览器、PPT软件和答辩记录。不同类别分开统计，任何NOT_RUN不能写成PASS。

本包的reference_deck与expected数据是人为编写测试资产，不是应用生成结果。生产执行路径不得读取evaluation、expected目录，测试fixture必须显式APP_MODE=fixture且界面可见，不能用于伪造live演示。

## 2. 模块单测

解析：正常文本、中文、重名不同内容、重复同内容、空白、扫描、加密、损坏、混合页、超限、跨目录路径。切块：物理页不跨、Unicode归一化、重叠位置与hash稳定、短页、重复引文定位歧义。

检索：中文术语、NVIC/CMSIS混合、同义改写、无匹配、无关资料、多个教学目标覆盖；排序分数不是置信度。证据：未知ID、跨项目ID、错误页码、伪造quote、同页多次相同quote、引用支持错误、来源冲突、derived缺推理说明。

Deck/编辑：Schema错误、重复ID、fact找不到claim、未用claim、拆页内容缺失、超页数、共享claim修改污染非目标页、候选不更新current、并发冲突、恢复创建新版本、旧corpus版本不可正式导出。

Job：幂等同请求同job、不同请求同key返回409、取消不提交、重启中断、Worker只持有一个项目写锁、渲染失败不丢已提交版本、轮询非幂等误重发防护。

## 3. 真实模型测试

开发模型先过码道工具8项smoke；应用模型另测计划、结构JSON、引用定位、语义支持、改写、split与资料不足。至少使用正向、变体、负向三类资料；不能只背一份STM32笔记。

每一请求记录model/provider/参数版本/提示版本/耗时/usage/attempt。一次修复重试仍失败，返回清楚错误；不能在测试时无限重试直到出现好结果。

应用live目标：至少连续3次完整演示成功；每次基于真实上传而非读取expected JSON。所有正式导出的事实块有合法引用；人工抽查所有reference demo页的关键结论。换模型后重跑smoke和黄金链，不仅改.env就宣称无损替换。

## 4. 导出与界面

PPTX检查结构、页数、可编辑文本对象；目标WPS/PowerPoint打开并修改标题保存。预览与导出均标版本。截图只能证明截图对应系统状态，不能替代PPT软件打开。

前端端到端：创建→逐个上传→计划→教师确认→候选生成→应用→看来源→拆页→确认→恢复旧版生成新版本→导出→刷新恢复。另测401、409、422、超时、取消、扫描件、预览降级。

纯结构预览是允许降级，但必须说明。高保真页面截图失败不能显示另一版本缓存；导出失败也不能返回空文件或图片型PPT作为成功。

## 5. 量化目标（设计目标，不是实测成绩）

定位合法率：正式输出fact引用100%可定位，这是门禁。语义支持率：按人工审核标注统计，不使用模型自评分代替真值。检索：evaluation中每条有相关页的case在Top8命中至少一条预期页；未达到需报告，不为提高数字删掉难例。

编辑：非目标页语义hash保持100%不变；拆页后声明保留的claim集合无缺失。恢复：目标语义内容一致、版本号严格递增。韧性：故障后旧已提交版本与导出文件可获取。

性能：记录上传解析、计划、生成、核验、导出的p50和最大值；初始交互目标8页生成不超过作业600秒上限，不能保证固定几秒。第三方网络和模型延迟计入整体，不能只报本地render耗时。

## 6. 验收报告格式

使用templates/test-report.md：环境、commit、case IDs、实际命令、退出码、时间、结果、失败与未测。测试与产品实现同轮提交；禁止改低assertion、跳过失败用例或mock真实外部链后称已联调。

文档中的规划任务、附带可运行的包校验器和未来业务测试命令要分开。当前只执行tools/validate_pack.py；项目M0完成前不存在pytest全绿的业务结论。
